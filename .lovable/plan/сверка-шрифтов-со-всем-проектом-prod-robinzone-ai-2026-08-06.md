## Что проверено

Сравнил подключение шрифтов, токены и реальные вычисленные стили на живой странице.

| Что | Оригинал | У нас |
| --- | --- | --- |
| Подключение | Google Fonts: Plus Jakarta Sans 200–800 + курсивы 400/500, JetBrains Mono 300–500 | тот же запрос (в `head` корневого маршрута) |
| Токены | sans / display / serif — Plus Jakarta Sans; mono — JetBrains Mono | те же четыре токена, значения совпадают |
| Body | 15px / 1.55 / вес 400 / `rlig, calt, ss01` | совпадает |
| Заголовки | h1–h6: Jakarta, `-0.025em`, `line-height 1.05`, 700; h1 — 800 | совпадает |
| `.font-display` / `.font-body` | есть | есть |
| `code, kbd, pre, samp` | JetBrains Mono | есть |
| Инпуты на мобильном | 16px | есть |

Замер в браузере: все элементы страницы (h1–h4, p, button, a, span, div) рендерятся Plus Jakarta Sans, веса h1 = 800, h2/h3 = 700 — как в оригинале. Инлайновых serif-переопределений в коде не осталось.

**Вывод: система шрифтов уже перенесена и совпадает 1:1. Отдельного переноса шрифтов не требуется.**

## Что всё-таки отличается в базовых стилях (не шрифты)

В `src/index.css` оригинала есть три блока, которых у нас нет, — они влияют на общий вид, но не на типографику:

1. Тонкий скроллбар 4px (`::-webkit-scrollbar` с полупрозрачным ползунком).
2. Правила для медиа: `img, video, svg, canvas, iframe { max-width: 100%; display: block }` + возврат размеров для `svg.lucide` и `[data-fixed-size]`.
3. Мобильный инвариант вьюпорта: `inline-size/max-inline-size: 100% !important`, `overflow-x: hidden !important` и `min-inline-size: 0` для всех элементов на `max-width: 767px` / `pointer: coarse`, плюс фолбэк `@supports not (overflow: clip)`.

## Что сделаю (если подтвердите)

Перенесу эти три блока из `src/index.css` оригинала в `@layer base` файла `src/styles.css` дословно, адаптировав только синтаксис под Tailwind v4. Файлы компонентов не трогаю.

Если нужны только шрифты — правок не потребуется вообще, всё уже совпадает.
